# Telegram Moment 重写设计与可行性验证

日期：2026-10-26

状态：用户已确认，进入实施。基线：`108de0b`。

## 目标与约束

用户要求接手并完全重写当前在 Halo 中难以使用的插件，先查阅文档并验证关键集成能力。

- 保留 Telegram → Halo 瞬间的单向发布用途，以及现有频道、私聊、相册、编辑、命令、作者、日志和可选回复功能。
- 编译、自动化测试和 Halo 启动均使用 WSL 中的 Docker。
- 真实 Token 当前不在本地。需要真实 Telegram 验证时，打开可见浏览器，由用户输入；不得把 Token 放入仓库、日志、报告或截图。
- 中文界面、注释和文档，英文日志。
- 不修改用户原有 Halo 数据。测试使用独立容器、数据卷和端口。
- 工作区原有 `plugin.yaml`、`ui/pnpm-lock.yaml` 未提交修改必须保留其意图，不直接覆盖或回退。前者拉取后出现重复依赖键，重写时合并为一处并记录版本选择。

## 最新代码调查

以下结论只适用于拉取后的基线；此前读取的旧实现不再作为当前事实。

1. 频道处理入口对 `message.from` 无条件解引用。Telegram 官方文档明确允许频道消息没有该字段；关闭调试日志也不能阻止参数求值。已通过真实 SDK 消息对象复现：`ChannelProbeTest` 断言合法频道消息必须进入 MessageHandler，实际发生空指针、断言失败。
2. 附件上传和查询通过未认证的 localhost HTTP 调用控制台接口。隔离 Halo 2.22 实测匿名上传请求跳转到登录页，无法返回附件对象。
3. `apiEndpoint` 只传给请求客户端，没有传给长轮询注册，因此收消息和下载可能使用不同端点。
4. 编辑先删旧内容及附件，再创建新内容；失败会丢失旧内容，成功也改变 Moment 身份。普通消息和 `/redo` 没有幂等约束。
5. 相册只存内存，以相册 ID 单独作为键，且只关联首条消息；未覆盖重启恢复和任意成员编辑。
6. `/rm` 在统一来源过滤之前执行；普通群消息被归入“私聊”，非法 Chat ID 配置被忽略后变为放行。
7. 文本转换没有转义 HTML，没有处理嵌套实体；附件失败后继续发布并可能回复成功。
8. 拉取后作者校验已经存在，Moment 使用编译 stub 与插件依赖加载实际类型。不能继续把旧版的空作者、自定义类型问题当作最新版本的已确认根因。
9. Halo 2.22 支持普通 Controller；瞬间 1.15.0 会为缺失审核状态补值。两者均不是已经证实的阻断原因。
10. 当前工作区 JAR 在真实 Halo 安装 API 返回 HTTP 400：`plugin-dependencies-with-wrong-versions`，实际读取的是第二处声明 `>1.15.0`，拒绝已启用的瞬间 1.15.0。

## 技术选择

以下方案已经用户确认。

- Java 21、Halo 2.22.11 API、Vue 3 和现有 Rsbuild 构建方式继续使用；最低 Halo 要求与实际 API 基线保持一致。
- 瞬间兼容基线为 1.15.0，依赖声明使用 `>=1.15.0`；至少验证 1.15.0，并选择一个与 Halo 2.22 兼容的后续版本做兼容测试。
- 移除复制第三方模型的 stub。通过 Halo `Unstructured`/通用扩展接口读写 `moment.halo.run/v1alpha1`，保留未知字段、状态、metadata 和乐观锁版本；不注册或注销瞬间的 Scheme。
- 注入 Halo `AttachmentService`，使用显式作者上传重载与 `getPermalink`，不回调 localhost 控制台，不要求用户配置 Halo 管理员 Token。
- Telegram 传输封装为可替换的独立接口。默认使用 Java HTTP 客户端与 JSON 实现必要的 Bot API，统一轮询、文件和回复端点，移除不必要的 SDK 生命周期耦合。最终是否保留 SDK 由编译及模拟端点验证决定，不能影响功能验收。
- 不引入外部数据库、Redis 或消息队列；同步状态保存在 Halo 自定义扩展资源中。

## 对用户可见的行为

### 配置与状态

保留现有配置组、字段名和含义；新增必要字段时提供兼容默认值。配置仍由 Halo 插件设置保存，管理页提供明确的配置入口。保存后显示“配置待应用”，通过“应用配置并重启”形成清晰边界。

启动先检查 Token、作者存在、瞬间可用、存储策略及 Chat ID 格式。私聊启用但没有允许的用户 ID 时不启动私聊发布，并显示明确错误；频道 ID 留空继续保持监听 Bot 可见频道的旧语义并在界面说明。命令与普通消息共用来源检查。群聊、超级群服务消息和本 Bot 回复均不作为私聊内容发布。

状态至少区分未配置、启动中、运行、重连中、配置错误、停止，显示最后成功轮询、最后成功发布及经过脱敏的错误。状态查询不请求 Telegram，重启结果不能把启动失败报告为成功。

### 消息和内容

- 支持文本、照片、图片相册、Animation/GIF、静态贴纸；补齐普通视频及图片/视频混合相册。
- 视频贴纸按视频处理；TGS 动画贴纸无法直接由浏览器展示时标记为不支持并说明原因，不伪装成成功图片。音频、任意文档和 Telegram 新式 rich message 暂不纳入本次范围。
- HTML 转义原文和属性，校验链接协议；按 UTF-16 偏移处理实体、emoji、嵌套格式及换行。越界实体忽略并保留原文，不使整条消息丢失。
- Hashtag 去重并转换为瞬间标签，屏蔽标签按完整标签匹配，避免 `#ad` 误伤 `#admin`。
- 保留原文到 `content.raw`，渲染结果到 `content.html`，作者及公开/审核字段明确设置。

### 幂等、编辑和删除

每个 Bot 身份下，以 Chat ID + Message ID 建立稳定映射；相册使用 Chat ID + Media Group ID，并记录所有成员 Message ID。消息重复投递不会产生重复瞬间。

编辑原地更新同一 Moment，保留身份、评论关联和未知字段。仅替换发生变化的媒体，先准备新附件，再写 Moment，最后清理已不使用的旧附件。失败保留旧内容并回收本次新附件；回收失败留下可重试记录。

频道 `/rm` 回复目标消息删除对应 Moment，回复任意已知相册成员均删除整个相册；不存在时按幂等成功处理。`/redo` 对已有记录重新同步，对未记录但含可处理内容的目标创建记录，不制造重复。命令不发布为正文。

普通频道消息删除没有可依赖的通用删除事件，本次不承诺 Telegram 原生删除自动同步；使用 `/rm`。不实现双向编辑或历史频道全量导入。

### 失败与恢复

轮询拿到 Update 后先落盘，再推进持久化 offset；落盘失败不确认该 Update。重启后恢复待处理记录。相册按消息 ID 排序、按最后一条到达时间延迟合并，编辑成员时从已存成员合成整个相册，标题取首个非空 caption。

单个串行发布工作者保证同一条内容的顺序；网络和服务错误有限次数指数退避，429 尊重 `retry_after`，权限/配置错误不忙循环。持续失败显示在管理页，可重试。后续编辑可以替代失败旧版本，但不能被旧版本覆盖。

默认整条发布成功才标记成功；附件失败不发布残缺相册或空瞬间。队列容量、媒体字节数、超时及保留期有明确上限；达到上限时停止确认新 Update 并展示原因。已完成记录保留同步所需映射，冗余原始负载和成功日志定期清理。详细数值由实施者依据测试确定并写入文档。

Bot 停止或配置切换取消轮询与旧工作者，等待当前有界操作结束后释放资源。旧 Token 下的任务不得被新 Token 错误执行；任务按 `getMe` 返回的 Bot ID 隔离。

### 日志和回复

保留可选运行日志，日志统一英文且脱敏，不记录 Token、完整请求 URL、原始配置 JSON 或私聊正文。界面中文提示明确区分日志未开启、没有记录和获取失败。

保留频道及私聊可选处理回复与延迟删除。回复只针对已授权且支持的消息，成功、失败分开显示；回复失败不能改变发布结果。默认关闭主动回复，避免开启测试后自动发消息。回复消息 ID 纳入忽略集合，防止频道自回复形成循环。

## 迁移与兼容

保留插件 ID、配置名称和主要字段。识别旧注解 `messageId/chatId/attachmentNames`，首次匹配时转换成命名空间注解及新映射，不重写无关瞬间。不自动删除既有重复内容或无法确认归属的附件。已有配置缺少新增必填信息时明确报错，不能默默扩大来源权限。

已有频道/私聊回复配置继续尊重；“默认关闭”仅用于新配置。UI 与后端使用一致的受保护 API 及权限声明，日志与控制操作只向有管理权限的用户开放。

## 验收

1. WSL Docker 中后端测试、前端类型检查、前端测试和完整打包通过，插件 JAR 可安装、启用、停用、重启；无残留线程。
2. 无 Token 下，模拟 Bot API 驱动真实 Halo + 瞬间：文字、带格式文字、图片、相册、编辑、重复投递、`/rm`、`/redo`，验证瞬间 API 和附件文件，而非只验证 mocked 方法调用。
3. 验证缺失 `from`、空 file size、非法 ID、错误 Token、断网、429、附件失败、重启恢复、相册成员编辑、未授权命令、群聊误入、HTML 注入及配置切换。
4. 页面实际显示配置错误、运行状态、失败重试和脱敏日志；没有将请求失败显示为正常停止或操作成功。
5. 验证旧配置和旧注解迁移；正常更新保留 Moment 名称及无关 metadata/status。
6. 真实 Telegram 单独验收：可见浏览器中由用户输入测试 Token；测试频道/私聊由用户发送消息。未完成此步骤不得宣称真实 Bot 链路已通过。主动回复的实际发送仅在用户明确开启并授权测试时执行。
