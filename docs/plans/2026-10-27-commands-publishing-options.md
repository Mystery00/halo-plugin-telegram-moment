# 命令、发布选项与资源选择器

日期：2026-10-27。基于 `main@7f3c960` 开发，分支为 `codex/telegram-commands-publishing-options`。

## 本轮需求

用户要求在当前环境实现以下改动并提交 PR，由 Windows 上的 Codex 拉取后进行实际 Halo/Telegram 运行验证：

1. 补齐、修复频道和授权私聊的 `/rm`、`/redo`。
2. 提供新瞬间可见性、自动审核、默认标签、正文前后缀、原消息链接等明确发布选项。
3. 将发布者、附件存储策略、附件分组改成资源选择器。

本轮不改变正式版本标签，不发布到应用市场。功能验证完成后再决定正式版本。

## 关键实现与兼容约定

### 命令

- `TelegramCommand` 统一识别独立文字消息中的命令，支持 `@当前Bot` 后缀；caption 中的斜杠内容保持普通正文。
- 命令发送者和被回复目标都要通过现有来源限制，且位于同一会话。其他 Bot 的命令忽略；缺目标、无效参数、未知命令、帮助请求均产生提示，不发布为瞬间。
- `/redo` 使用回复中的最新目标快照，只替换这一相册成员；`/rm` 使用现有成员映射删除整组。重复投递不新增同步记录。
- 使用 `momentKnown` 区分已确认存在的瞬间与失败发布预分配的名称。未知目标不能假报删除成功；删除已提交但响应丢失时仍能恢复为幂等成功。旧版 `DELETED` 可能来自空删除，因此不能单凭该状态推断目标存在过；只从旧 `SUCCEEDED` 或实际 Moment 读取补足证据。
- 命令请求、结果和 Telegram 消息清理队列保存在当前 Bot 的 `BotCursor` 中，与游标一起保存。命令和目标记录持久化失败时不推进接收游标。
- Halo 操作完成后才持久化清理意图。命令反馈和 Telegram 删除各自有限重试，不能反向重做已完成的 Halo 操作；旧 Bot 的队列不会被新 Bot 消费。
- 主动命令反馈独立于普通消息自动回执开关。命令回复允许目标已不存在，以便命令被清理后仍可补发结果。
- 成功命令清理默认开启；原消息联动删除默认关闭。只在成功的 DELETE 操作后清理原消息，已知相册按记录的全部成员清理。

### 发布配置

- 旧配置保持公开、自动审核通过、空默认标签、空前后缀、不附来源链接的默认行为。
- 新建使用默认可见性、审核状态和发布者；编辑保留原 `owner`、`visible`、`approved`、`approvedTime`，包括原值为 false、null 或缺失的情况。
- 标签按中英文逗号或换行拆分，去掉可选 `#` 前缀、去空和去重，再与正文 hashtag 合并。最多 64 个默认标签，每个最多 64 个 UTF-16 单元。
- 前后缀作为独立纯文本段落渲染并转义；各最多 4096 个 UTF-16 单元。原消息文本独立转换，确保原实体偏移不被前缀改变；raw 与 html 均包含实际修饰内容。
- 来源链接优先使用严格校验后的公开频道 username；缺失或不合法时，按 Telegram 官方数字 ID 规则生成 `t.me/c/` 链接。私聊始终不生成链接。相册指向首条已记录消息。
- `IncomingMessage` 新增可选频道用户名；保留原构造方式，旧 JSON 缺少该字段时仍可反序列化并回退到数字链接。
- 为避免 `/redo` 破坏旧多媒体瞬间，接管旧注解资源时，如果当前媒体成员数不足以覆盖原媒体列表，则在上传、清理前拒绝覆盖并保留原内容。每次提交或乐观锁重试前还会重新检查最新 Moment，防止上传期间新增的旧媒体被覆盖。该保护不重建旧版未保存的成员映射，也不能让未记录成员自动关联旧相册。

### 资源选择器

使用 Halo 2.22.11 自带的 `userSelect`、`attachmentPolicySelect`、`attachmentGroupSelect`，不增加 UI 依赖或管理 API。字段仍为 `momentOwner`、`storagePolicy`、`storageGroup`；列表显示名称，保存资源 name。关闭自动选择首项，分组允许清空为 `""`，已有配置无需迁移。

官方兼容性依据：

- [Halo 2.22.11 FormKit 注册](https://github.com/halo-dev/halo/blob/v2.22.11/ui/src/formkit/formkit.config.ts)
- [用户选择器](https://github.com/halo-dev/halo/blob/v2.22.11/ui/src/formkit/inputs/user-select.ts)
- [存储策略选择器](https://github.com/halo-dev/halo/blob/v2.22.11/ui/src/formkit/inputs/attachment-policy-select.ts)
- [附件分组选择器](https://github.com/halo-dev/halo/blob/v2.22.11/ui/src/formkit/inputs/attachment-group-select.ts)
- [Telegram 频道 ID](https://core.telegram.org/api/bots/ids#supergroup-channel-ids)
- [Telegram 消息链接](https://core.telegram.org/api/links#message-links)

## Windows Codex 接管与实际运行验证

### 获取并构建

先阅读仓库 `AGENTS.md` 与本文件，保留工作区已有修改。使用 GitHub CLI 可按 PR 编号执行 `gh pr checkout <PR编号>`，或获取上述分支。仅在专用测试 Halo 使用测试脚本和模拟凭据。

在 Windows PowerShell 的仓库根目录执行：

```powershell
wsl --exec bash scripts/build.sh '-Pversion=1.1.0-rc.1'
```

得到 `build/libs/plugin-telegram-moment-1.1.0-rc.1.jar`。安装到专用 Halo 实例，至少覆盖最低兼容组合 Halo 2.22.11 / 瞬间 1.15.0，以及实际使用的当前版本；不同 Halo 版本使用独立数据卷。该命令只构建本地测试制品，不创建 Release。

| 场景 | 期望结果 |
| --- | --- |
| 升级后打开配置 | 已有发布者、策略、分组正确回显；无需重新输入资源名。 |
| 选择不同用户和策略，清空分组 | 保存的是对应资源 name；分组为空；重启 Bot 后新附件写入所选策略。 |
| 保持旧默认配置，发送文字和双图相册 | 与原同步行为一致，相册仍为一个瞬间。 |
| 新建选择私有、关闭自动审核 | 新瞬间为 PRIVATE、approved=false，没有自动审核时间。 |
| 默认标签与正文 hashtag 重复 | 标签去重；中文逗号、换行、带 # 都能正确解析。 |
| 前后缀含换行、HTML字符，正文含 😀 和粗体/链接 | 前后缀显示为纯文本，正文格式位置正确；raw 与页面内容一致。 |
| 开启来源链接，测试公开频道、私有频道、私聊 | 公开频道使用 username 链接，私有频道使用合法数字链接，私聊不产生链接。 |
| 在 Halo 改原瞬间的发布者、私有状态或审核状态，再编辑或 redo | 保持人工修改的管理字段，内容更新且 Moment 名称不变。 |
| 授权私聊回复原消息发送 `/redo` 或 `/redo@Bot用户名` | 更新原瞬间，不增加 `/redo` 文本瞬间或重复记录。 |
| 频道或私聊回复相册非首成员发送 `/redo` | 保留整组其他成员，更新该成员内容；Moment 名称不变。 |
| 回复已知相册任意成员发送 `/rm` | 删除整组瞬间及关联附件；默认保留 Telegram 原消息。 |
| 开启联动删除后再次测试 `/rm` | 只在 Halo 删除成功后尝试清理已记录的 Telegram 原消息；redo 不删除源消息。 |
| 清理成功命令开关开启/关闭 | 分别清理或保留成功命令；失败命令及帮助请求始终保留。 |
| `/rm` 无目标、未知命令、发给其他 Bot、回复 Bot 回执、未授权来源 | 不产生错误瞬间，不执行未授权操作；授权命令收到相应提示，其他 Bot 命令被忽略。 |
| 对从未发布的消息执行 `/rm` 并重试 | 明确无法定位，不宣告删除成功，不删除 Telegram 源消息。 |
| 相同更新重复投递、Bot 重启、重复 `/rm` | 不重复创建瞬间；已知删除保持幂等，未完成反馈和清理继续恢复。 |
| 模拟 Telegram 删除或回执请求失败 | Halo 成功结果保留，不再次发布/删除；日志显示独立重试。 |
| 在隔离数据中构造旧双图瞬间，但只提供单成员 redo | 明确关联不完整；原瞬间和两个附件不变。旧单图仍可正常接管。 |

真实网络验收由用户在专用测试频道/私聊发送消息，或按当次明确授权执行。不要使用生产旧相册验证破坏性路径，不在聊天、日志或提交中输出真实 Token。
